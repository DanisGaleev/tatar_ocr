# Tatar OCR («Кара куян»)

Автономная система компьютерного зрения и OCR для распознавания и верификации рукописных учебных бланков по татарскому языку на мобильных и встраиваемых устройствах.

Проект разработан как инженерное решение полного цикла: от проектирования бланка и сбора данных до обучения специализированной нейросетевой архитектуры, квантования весов, переноса конвейера на C++20 и построения кроссплатформенного рантайма без дублирования логики.

---

## Ключевые результаты и метрики

Система протестирована на бенчмарке из 12 реальных бланков со сложным рукописным детским почерком (449 символов, 57 полей):

| Метрика | Значение | Описание |
| :--- | :--- | :--- |
| **Acc_char** | **96.88%** (435/449) | Посимвольная точность распознавания |
| **CER** | **3.12%** | Уровень ошибок посимвольного распознавания (Character Error Rate) |
| **R_Tatar** | **97.33%** (73/75) | Полнота распознавания 6 специфических татарских букв (Ә, Ө, Ү, Җ, Ң, Һ) |
| **FEM** | **78.95%** (45/57) | Доля полей, распознанных с абсолютным совпадением (Field Exact Match) |
| **FFM (Lev <= 1)** | **96.49%** (55/57) | Доля полей с не более чем одной ошибкой |
| **HCER (80%)** | **1.78%** | Ошибка при верификации оператором сомнительных ячеек (Human-Assisted CER) |
| **Размер модели** | **1.0 МБ** | Квантованная INT8 ONNX модель (против 3.8 МБ в FP32) |
| **Инференс** | **< 1 сек** | Время обработки полного бланка (выравнивание + предобработка + батчевый инференс) на CPU |
| **Автономность** | **100% offline** | Полная работа на устройстве без обращения к сети (соответствие 152-ФЗ) |

## Архитектурные и инженерные решения

### 1. Кроссплатформенное ядро на C++20 без дублирования кода
* Вся критическая логика обработки вынесена в библиотеку `tatar_ocr_core` на C++20:
  * Детекция 4 маркеров ArUco (`DICT_4X4_50`) и проективное преобразование к эталонному холсту A4 (`cv::warpPerspective`).
  * Поиск сетки и привязка углов таблицы (corner snapping) для компенсации механических деформаций листа.
  * Адаптивная очистка границ ячеек (border suppression) с помощью морфологических операций для исключения шума от печатной сетки.
  * Пакетный инференс через ONNX Runtime C++ API: все непустые ячейки листа объединяются в единый тензор `(N, 1, 64, 64)`, исключая накладные расходы на последовательные вызовы.
* Библиотека собирается в нативный Python-модуль (`pybind11`) для исследований и бенчмаркинга и без изменений портируется в Android NDK.

### 2. Декларативная спецификация как единый источник правды
* Геометрия бланка, координаты маркеров, параметры сетки ячеек (11 строк, 13 колонок), правила фильтрации шума, алфавит и список моделей вынесены в `pipeline_spec.json`.
* Любые изменения параметров формы или порогов уверенности применяются одновременно в C++, Python и мобильном приложении без перекомпиляции кодовой базы.

### 3. Специализированная ML-архитектура под татарскую кириллицу
* **Проблема:** стандартные OCR-модели плохо различают тонкие диакритические элементы специфических букв татарского алфавита (хвостики у **Җ, Ң**, перекладины у **Ө**, верхние штрихи у **Ү**, точки у **Ё, Й**) на детском почерке.
* **Решение:** разработана архитектура `MultiScaleHandwrittenCNN` на 39 классов:
  * Параллельные сверточные ветки с ядрами разного масштаба ($3\times3$, $5\times5$, $7\times7$) для одновременного извлечения общих контуров и мелких штрихов.
  * Механизм внимания Squeeze-and-Excitation (SE-блоки) для калибровки важности каналов признаков.
  * Двухэтапная стратегия обучения с аугментацией диакритики, взвешиванием редких классов и тонкой настройкой на реальных сканах.

### 4. Оптимизация под мобильные устройства (Edge AI)
* Модель экспортирована в формат ONNX и квантована в **INT8**. Размер сокращен до **1.0 МБ**, что позволяет встраивать модель напрямую в APK без фоновой загрузки.
* Точность квантованной модели на реальном бенчмарке полностью идентична исходной FP32 модели (Acc_char = 96.88%).

### 5. Концепция Human-in-the-Loop (HITL)
* Для каждой ячейки вычисляется вероятность и возвращаются Top-3 кандидата.
* При уверенности ниже заданного порога ячейка помечается флагом для проверки человеком. Это снижает итоговую ошибку системы (HCER) до 1.78%, требуя от оператора всего 8 точечных проверок на 449 символов.

## Технологический стек

* **Системная разработка:** C++20, CMake, `pybind11`, `nlohmann/json`.
* **Компьютерное зрение:** OpenCV (C++ / Python), ArUco Marker Detection, Homography, Morphological Processing.
* **Машинное обучение:** PyTorch, Torchvision, ONNX, ONNX Runtime (C++ / Python), INT8 Quantization.
* **Инструменты и инфраструктура:** Python 3.12, PowerShell, Git, встроенный веб-интерфейс для визуализации (чистый HTML/JS без внешних зависимостей).

## Быстрый старт

### 1. Сборка нативного C++20 ядра
Требуются CMake версии не ниже 3.20, компилятор с поддержкой C++20, установленные OpenCV и ONNX Runtime:

```powershell
cd native
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

### 2. Запуск веб-визуализатора
Интерактивный интерфейс с drag-and-drop загрузкой бланков, подсветкой ячеек и инспекцией Top-3 кандидатов:

```powershell
python visualize_pipeline.py --serve --port 8080
```
Интерфейс доступен в браузере по адресу `http://127.0.0.1:8080`.

### 3. Оценка качества на эталонном бенчмарке
Расчет всех метрик (Acc_char, CER, R_Tatar, FEM, FFM, HCER) на 12 канонических бланках:

```powershell
python v3/evaluate_blanks.py --onnx models/tatar_ocr_v4_handwritten39_int8.onnx
```

## Схема интеграции в Android

Для исключения дублирования алгоритмов нативное C++ ядро подключается в Android-приложение напрямую через Android NDK:

1. **Компиляция ядра:** `native/src/tatar_ocr.cpp` подключается в `CMakeLists.txt` проекта Android Studio и компилируется под целевые архитектуры (`arm64-v8a`, `armeabi-v7a`).
2. **Зависимости:** Подключаются сборки OpenCV Android SDK и `onnxruntime-android` (из репозитория Maven Central / AAR).
3. **Ресурсы:** Файлы `pipeline_spec.json` и `tatar_ocr_v4_handwritten39_int8.onnx` помещаются в директорию `assets/`.
4. **Интерфейс взаимодействия (JNI):** Небольшой JNI-слой принимает байты изображения или `Bitmap`, передает их в `NativeBlankScanner` и возвращает в Kotlin готовый список распознанных полей со статусами уверенности.
