# Spec — Server-Side Blank Photo Recognition & Verification

## Goal

Enable the mobile/web client to upload a photographed test blank to the FastAPI backend for server-side recognition via the C++20 `tatar_ocr_native` OCR pipeline and verification against the assembled test's answer key, returning the complete recognition and grading payload identical in information to local on-device scanning.

## Non-goals

- Persisting uploaded student blank photos to disk, object storage, database, or logs (strict 152-ФЗ transient-in-RAM processing).
- Modifying `native/` C++20 core, `pipeline_spec.json`, or ML model weights (`tatar_ocr_v4_handwritten39_int8.onnx`).
- Removing or breaking existing Zero-Photo `POST /api/v1/submissions` or `/batch-sync` endpoints.

## Assumptions

- `tatar_ocr_native` (built from `native/`) and `models/tatar_ocr_v4_handwritten39_int8.onnx` + `pipeline_spec.json` are available on the server host (or configurable via `NATIVE_BUILD_DIR` / `TATAR_OCR_NATIVE_DIR`).
- QR codes generated by `backend/app/generators/pdf_blank.py` encode JSON with `tid` (assignment_id), `var` (variant_id), `page`, `tot`, `n_q` (and optionally `stu_id`).

## Acceptance Criteria

- `AC-1`: Bridge layer (`backend/app/services/blank_scanner_bridge.py`) loads `tatar_ocr_native.NativeBlankScanner` with `pipeline_spec.json` and v4 INT8 ONNX model, decodes image bytes in RAM, extracts QR metadata, and returns typed native scan results.
- `AC-2`: Recognition service (`backend/app/services/blank_recognition_service.py`) validates image bytes in RAM without persisting or logging raw photos, runs C++ scan via threadpool, resolves test/variant/student/teacher settings, verifies answers with `verify_test_submission`, computes HITL flags (`review_required`, `zero_touch`), builds `submission_draft`, and optionally persists when `auto_save=true`.
- `AC-3`: Endpoints `POST /api/v1/submissions/recognize` and `POST /api/v1/submissions/recognize-base64` handle valid images, invalid MIME/empty/oversized/corrupt payloads (`400`/`413`/`422`), missing explicit assignments (`404`), and `auto_save=true`.
- `AC-4`: Unit and API tests in `backend/tests/test_blank_recognition.py` thoroughly cover bridge, service, multipart & base64 endpoints, QR resolution, HITL flags, grading, `auto_save`, and adversarial error cases.
- `AC-5`: End-to-end verification on real blank photos (`samples/test_blank_phone_photo.jpg` and `benchmark/images/blank_01.jpg`) through the FastAPI app and real C++20 `tatar_ocr_native` core succeeds with expected OCR and verification output.
- `AC-6`: Full backend test suite passes after the final edit.
- `AC-7`: Living specs (`api_specification.md`, `openapi_specification.yaml`, `docs/adr/0004-zero-photo-backend-contract.md`, `docs/ARCHITECTURE.md`, `docs/STATUS.md`) are synced and Fresh-Context Evaluator review in `reviews/review.md` records verdict `accept`.
