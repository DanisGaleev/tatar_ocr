# Tatar OCR Blank Evaluation & Benchmarking Suite

This benchmark suite provides an objective, standardized evaluation harness for Tatar handwriting recognition on standardized examination blanks (answers forms). It supports end-to-end evaluation comparing predictions generated across diverse execution environments (Python backend/inference servers, mobile Kotlin/Android runtimes, React Native/iOS clients) against ground truth annotations.

---

## 1. Directory Structure

```text
benchmark/
├── README.md               # Architecture documentation, schema specification & guidelines
├── images/                 # Raw test blank photos / scanned forms (.jpg, .jpeg, .png)
│   └── blank_001.png       # Example input image
├── ground_truth/           # Gold-standard ground truth JSON annotations
│   └── blank_001.json      # GT annotations corresponding to blank_001.png
├── predictions/            # Model predictions exported from pipelines
│   ├── python_baseline/    # Output from Python BlankOCRScanner (blank_pipeline.py)
│   │   └── blank_001.json
│   ├── mobile_kotlin/      # Output from Android / Kotlin ONNX/TFLite runner
│   │   └── blank_001.json
│   └── react_mobile/       # Output from mobile frontend runner (if applicable)
│       └── blank_001.json
└── reports/                # Evaluation output artifacts, markdown reports & confusion matrices
    └── summary_latest.md   # Generated benchmark results
```

### Folder Roles
- **`images/`**: High-resolution scans and real-world smartphone photos of completed Tatar blank forms. File basenames (e.g., `blank_001`) serve as the canonical primary key linking images, annotations, and predictions.
- **`ground_truth/`**: Human-verified or synthetic gold-standard JSON annotations per blank form.
- **`predictions/`**: Inference outputs organized either by pipeline subfolder (`predictions/<pipeline_name>/<image_id>.json`) or directly by file ID (`predictions/<image_id>.<pipeline_name>.json`).
- **`reports/`**: Evaluation summaries generated by the benchmarking scripts, including Character Error Rate (CER), Form Exact Match (EM), Empty Cell Classification (F1), and Tatar letter confusion metrics.

## 2. Supported Character Set (Tatar Cyrillic)

All blank fields (student name and question rows) expect uppercase Tatar Cyrillic characters (**39 classes**):

```text
А Ә Б В Г Д Е Ё Ж Җ З И Й К Л М Н Ң О Ө П Р С Т У Ү Ф Х Һ Ц Ч Ш Щ Ъ Ы Ь Э Ю Я
```

Key Tatar-specific letters tracked specifically for misclassification against standard Cyrillic counterparts:
- **`Ә`** (vs `А`, `О`)
- **`Җ`** (vs `Ж`)
- **`Ң`** (vs `Н`)
- **`Ө`** (vs `О`, `В`)
- **`Ү`** (vs `У`, `Ч`)
- **`Һ`** (vs `Н`, `Х`)

## 3. Canonical JSON Schema Specification

Both Ground Truth (`ground_truth/*.json`) and Predictions (`predictions/*/*.json`) conform to a unified JSON format. This enables side-by-side metric computation.

### 3.1 Field Hierarchy & Cell Data Model

A form consists of:
1. **Metadata**: `image_id`, optional `form_id`, pipeline metadata.
2. **Student Name (`student_name`)**:
   - `text`: Compact string of the full name without inter-cell padding.
   - `cells`: Ordered list of individual cell recognition objects (typically 15-16 cells).
3. **Questions (`questions`)**:
   - Array of question items (`q_num`: 1..N).
   - Each item contains `text` (assembled string) and `cells` (ordered list of cell items, typically 8-12 cells).

### 3.2 Cell Object Attributes
| Field | Type | Required (GT) | Required (Pred) | Description |
| :--- | :--- | :--- | :--- | :--- |
| `cell_idx` | `integer` | Yes | Yes | 1-based index of the cell within the row. |
| `char` | `string` | Yes | Yes | Single uppercase character (`"А".."Я"`, `"Ә".."Һ"`). Empty cell is represented as `""` or `" "` (evaluator standardizes spaces to empty string). |
| `is_empty` | `boolean` | Yes | Yes | `true` if the cell contains no ink / is unwritten, `false` otherwise. |
| `confidence`| `float` | No (default 1.0/100.0) | Yes | Prediction confidence score in range `[0.0, 100.0]`. |
| `bbox` | `[int, int, int, int]` | No | Optional | `[x, y, width, height]` in rectified image coordinates (2100x2970 canvas). |
| `top_items` | `array` | No | Optional | Optional array of alternative hypotheses, e.g. `[{"char": "Ө", "conf": 87.5}, {"char": "О", "conf": 12.1}]`. |

## 4. Cross-Pipeline Export Guidelines

### 4.1 Python Pipeline (`blank_pipeline.py`)

In Python, the `BlankOCRScanner.process_image` method produces raw dictionaries. To save them in canonical benchmark format:

```python
import json
from pathlib import Path
from blank_pipeline import BlankOCRScanner

def export_python_prediction(image_path: Path, output_dir: Path):
    scanner = BlankOCRScanner()
    raw_res = scanner.process_image(str(image_path))
    
    image_id = image_path.stem
    payload = {
        "image_id": image_id,
        "pipeline": "python_blank_pipeline",
        "rectification_method": raw_res.get("rectification_method", "unknown"),
        "student_name": {
            "text": raw_res.get("student_name", ""),
            "cells": raw_res.get("student_name_cells", [])  # cell results
        },
        "questions": raw_res.get("questions", []),
        "stats": raw_res.get("stats", {})
    }
    
    output_dir.mkdir(parents=True, exist_ok=True)
    out_file = output_dir / f"{image_id}.json"
    with open(out_file, "w", encoding="utf-8") as f:
        json.dump(payload, f, ensure_ascii=False, indent=2)
```

### 4.2 Mobile Android (Kotlin) Runner

On Android devices executing on-device recognition (e.g. OpenCV Android SDK for ArUco rectification + ONNX Runtime or TFLite for cell classification), data structures serialize to the identical schema using `kotlinx.serialization` or `Gson`:

```kotlin
import kotlinx.serialization.Serializable
import kotlinx.serialization.encodeToString
import kotlinx.serialization.json.Json

@Serializable
data class BenchmarkPrediction(
    val image_id: String,
    val pipeline: String = "mobile_kotlin_onnx",
    val rectification_method: String = "ArUco 4-Point Geometry",
    val student_name: NameSection,
    val questions: List<QuestionSection>,
    val stats: ExecutionStats
)

@Serializable
data class NameSection(
    val text: String,
    val confidence: Float = 0f,
    val cells: List<CellResult>
)

@Serializable
data class QuestionSection(
    val q_num: Int,
    val text: String,
    val confidence: Float = 0f,
    val cells: List<CellResult>
)

@Serializable
data class CellResult(
    val cell_idx: Int,
    val char: String,
    val confidence: Float,
    val is_empty: Boolean,
    val bbox: List<Int>? = null
)

@Serializable
data class ExecutionStats(
    val total_letters: Int,
    val avg_confidence: Float,
    val questions_count: Int,
    val inference_time_ms: Long? = null
)

// Export helper
fun exportPredictionJson(prediction: BenchmarkPrediction): String {
    val json = Json { prettyPrint = true; encodeDefaults = true }
    return json.encodeToString(prediction)
}
```

## 5. Form-Level & Cell-Level Benchmark Metrics

The benchmark evaluator computes the following primary metrics:

1. **Field Exact Match (EM)**:
   $$\text{EM} = \frac{1}{N_{\text{fields}}} \sum_{i=1}^{N_{\text{fields}}} \mathbb{I}(\text{pred\_text}_i == \text{gt\_text}_i)$$
   Evaluated separately for:
   - Student Name Exact Match.
   - Question Answers Exact Match.
   - Complete Form Perfect Match (Student Name AND all Questions 100% correct).

2. **Character Error Rate (CER)**:
   $$\text{CER} = \frac{S + D + I}{N_{\text{chars}}}$$
   Computed globally across all non-empty characters, as well as per-field.

3. **Empty Cell Detection Accuracy**:
   - Confusion matrix of empty vs. non-empty cells (True Positives, False Positives, False Negatives).
   - Precision, Recall, and F1-score for ink detection (verifying models don't hallucinate letters in empty cells or drop faint ink strokes).

4. **Tatar-Specific Character Accuracy**:
   - Precision, Recall, and F1 specifically isolated for `Ә, Ө, Ү, Җ, Ң, Һ`.
   - Confusion matrix isolating Tatar letters vs Cyrillic visual twins (e.g., `Ө` vs `О`, `Ң` vs `Н`, `Ү` vs `У`).

## 6. Running Evaluations

Detailed commands for running evaluations against ground truth:

```bash
# Evaluate Python baseline predictions
python benchmark/evaluate.py --predictions benchmark/predictions/python_baseline/

# Compare Python baseline vs Mobile Kotlin predictions
python benchmark/evaluate.py --compare benchmark/predictions/python_baseline/ benchmark/predictions/mobile_kotlin/
```

Results and confusion heatmaps are saved to `benchmark/reports/`.
